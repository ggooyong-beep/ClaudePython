# 요구사항 해석 결정 기록

`OEM-SWR-001`(Rev 1.0, `BL-OEM-1.0`)에서 정의되지 않았거나 모호한 항목을 공급자(개발팀)가 결정한 기록이다.
모든 결정은 **공급자 가정**이며 OEM 확인 전까지 `상태: 확인 필요`로 관리한다. OEM이 다르게 답하면 해당 SWR, 설계, 테스트를 함께 수정한다.

| ID | 주제 | 결정 | 근거 | 상태 |
|---|---|---|---|---|
| DEC-001 | 우선순위 | 아래 "우선순위표"를 따른다. | 사양서에 순서가 없어 안전 영향이 큰 조건을 먼저 두었다. | 확인 필요 |
| DEC-002 | 평가주기 | 평가주기는 50 ms로 한다. | `SR-003`은 200 ms 초과 후 100 ms 이내 `DEGRADED`를, `SR-001`은 300 ms 이내 해제를 요구한다. 주기 100 ms 이하여야 100 ms 요구를 만족하고, 50 ms는 여유를 둔 값이다. | 확인 필요 |
| DEC-003 | `crash_status = PENDING` | 출력은 바꾸지 않고(직전 출력 유지) 이벤트만 기록한다. | `CONFIRMED`만 해제 조건이다. 미확정 값으로 해제하지 않는다. | 확인 필요 |
| DEC-004 | `DEGRADED` 출력 | 입력이 stale인 동안 직전 확정 출력을 유지한다. 모든 필수 입력이 다시 fresh가 되면 다음 평가주기에 정상으로 복귀한다. | 신뢰할 수 없는 입력으로 출력을 바꾸지 않는다(`SR-004`와 같은 보수적 방향). | 확인 필요 |
| DEC-005 | 일반 해제 허용 조건 (`SWR-004`) | 운전자 해제 명령은 유효 차속이 3 km/h 미만일 때만 적용한다. 3 km/h 이상이면 `LOCK`을 유지하고 이유코드 `RELEASE_DENIED_MOVING`을 기록한다. | `FR-001`의 수용기준이 "정지, 정상입력"을 전제하고, `FR-002`의 이동 판단 임계가 3 km/h이다. | 확인 필요 |
| DEC-006 | `gear` 입력 | 필수 입력으로 검증하고(P/N/D/R 외 값은 `INVALID`) 제어 판단에는 쓰지 않는다. | 어떤 요구도 `gear`로 동작을 정하지 않는다. | 확인 필요 |
| DEC-007 | 경계 방향과 시각 | "이하"는 경계 포함, "초과"는 경계 제외로 해석한다. 경과시간은 `VehicleSnapshot.timestamp_s − source_timestamp_s`로 계산하고 밀리초 정수로 반올림해 비교한다. | `SR-003`은 "200 ms 초과", `FR-003`은 "10초 이하"이다. 부동소수점 오차를 피한다. | 확인 필요 |
| DEC-008 | `SWR` 번호 | `SWR-001`~`SWR-021`은 사양서 9장 추적표의 설명으로 본문을 도출한다. `SWR-019`는 사양서에 근거가 없어 결번으로 둔다. 우선순위(DEC-001)와 평가주기(DEC-002)는 `SWR-022`, `SWR-023`으로 **제안** 추가한다. | 9장에 번호와 한 줄 설명만 있다. | 확인 필요 |
| DEC-009 | Python 버전 | `>=3.12`로 지정한다. 사양서의 3.12와 `CLAUDE.md`의 최신 안정 버전을 모두 만족한다. | 두 문서의 충돌 해소. | 확정 |
| DEC-010 | Web 시뮬레이터 | FastAPI로 상태조회와 시험 입력 API를 제공하고, 화면은 정적 HTML과 JavaScript(프레임워크 없음)로 만든다. | `IF-006`이 HTTP 오류를 언급한다. 의존성을 최소화한다. | 확정 |

## 우선순위표 (DEC-001)
위에서 아래로 평가하며, 상위 조건이 출력을 정하면 하위 조건은 적용하지 않는다. 좌·우 출력은 독립적으로 결정한다.

| 순위 | 조건 | 동작 | 관련 요구 |
|---|---|---|---|
| 0 | 입력 검증 실패, stale | 형식·범위 오류는 평가 전에 거절한다. stale이면 `DEGRADED`로 직전 출력을 유지한다(DEC-004). | `SR-003` |
| 1 | `crash_status = CONFIRMED` | 좌·우 `RELEASE` | `SR-001` |
| 2 | 화재, 과온, 성인 존재 중 하나가 TRUE | 좌·우 `RELEASE` | `FR-005` |
| 3 | `sensor_fault = TRUE` | 직전 확정 출력 유지, `FAULT` | `SR-004` |
| 3.5 | `crash_status = PENDING` | 직전 출력 유지, 이벤트만 기록 (DEC-003) | `SR-001` |
| 4 | 측별 후측방 접근위험 TRUE | 해당 측 `LOCK`, 해제 요청 억제 | `SR-002` |
| 5 | 측별 ISOFIX TRUE | 해당 측 `LOCK` | `FR-006` |
| 6 | `ignition_on = FALSE` | 좌·우 `RELEASE`, `OFF` 상태 | `FR-007` |
| 7 | 유효 차속 ≥ 3 km/h | 좌·우 `LOCK` | `FR-002` |
| 8 | 운전자 명령 | 선택 측에 적용(DEC-005 조건 포함) | `FR-001` |

## 상세 설계 중 추가된 해석 (DD-004)
- **DD-004** 접근위험으로 해제가 억제된 측에서 10초 이하 재입력으로 override가 성립하면, 그 측의 접근위험이 FALSE가 될 때까지 `RELEASE`를 유지한다. 같은 측에 `lock` 명령이 오면 override를 해제하고 `LOCK`한다. override를 유지하지 않으면 다음 평가주기에 접근위험 규칙(`SWR-005`)이 다시 `LOCK`을 걸어 override가 한 주기만 지속된다. 사양서는 override 이후 동작을 정의하지 않았다. 상태: 확인 필요.

## 사용자 확정 사항
- 성인 존재(순위 2)와 접근위험(순위 4)이 동시에 TRUE이면 성인 존재가 우선하여 `RELEASE`한다. (확정)
- ISOFIX(순위 5)와 시동 OFF(순위 6)가 동시에 성립하면 ISOFIX가 우선하여 해당 측 `LOCK`을 유지한다. (확정)

## 미결 사항 (OEM 확인 요청)
- DEC-001~008 전체는 공급자 가정이며 OEM 확인 전까지 `확인 필요`로 둔다.
