# System-Test-Skill

SW 요구사항(테스트 베이시스)으로부터 **실행 가능한** 시스템 테스트 케이스(TC)를 도출하고, 100% 양방향 추적성과 커버리지를 검증한 뒤 xlsx로 산출한다.

## 절대 규칙

1. **양방향 추적성 100%**: 모든 TB(테스트 베이시스) 항목 ≥1개 TC에 연결, 모든 TC(제안 제외) ≥1개 TB에 연결.
2. **커버리지 100%**: 모든 TB 항목이 TC로 검증됨. 커버리지는 `scripts/build_xlsx.py`의 검증 통과로만 주장한다 — 손으로 "100%"라고 쓰지 않는다.
3. **쓰레기 TC 금지**: 커버리지만 채우는 TC(같은 클래스 중복, 판정 불가한 기대값, 의미 없는 입력 변형)를 만들지 않는다. 모든 TC는 "이 TC가 실패하면 어떤 결함/위험을 발견하는가"를 `purpose`에 답해야 한다.
4. **실행 가능성**: 입력값은 구체적 수치/신호/단위, 절차는 번호 매긴 조작 단계, 예상 출력은 관측 가능하고 판정 가능한 값(허용오차·시간 포함). "정상 동작", "적절한 값", "등" 금지.
5. **"제안" 표시**: 사용자 문서에서 직접 도출되지 않고 내가 추가한 TC는 `suggested: true` → 시트에 "제안" 표기 + ID에 `-S` 접미사 + 제목 앞 `[제안]`.
6. **기능/비기능 시트 분리**.
7. **임의 가정 금지**: TB에 없는 값(임계값, 타이밍)은 만들어내지 않는다. 불명확하면 TC를 만들지 말고 `open_issues`로 사용자에게 질문 목록을 제시한다.

## 워크플로

### 1. 입력 확인
- 테스트 베이시스: SW 시스템/SW 요구사항, 인터페이스 명세, 아키텍처(필요 시). 파일 경로 또는 붙여넣기.
- **TC 양식**: 사용자가 양식(xlsx/표/컬럼 목록)을 주면 그 컬럼을 `columns`로 매핑해 그대로 따른다. 없으면 기본 항목: `테스트 케이스 ID, 테스트 베이시스 ID, 테스트 목적, 입력값, 절차, 예상 출력값, 사용한 테스트 기법` (+ 사전조건, ASIL, 제안 여부, 환경은 보조 컬럼으로 추가 가능).
- ASIL 등급(없으면 TB에 표기된 것 사용, 없으면 질문), 테스트 환경(HIL/SIL/실차).

### 2. 테스트 베이시스 분해
- TB ID 부여/수집(원문 ID 우선). 한 요구사항에 여러 검증 가능 조건("and", 복수 shall, 복수 상태)이 있으면 원자 항목으로 나누되 **원 ID 하위 번호**(`REQ-12.1`)로 추적.
- 각 항목을 `functional` / `nonfunctional`(성능·타이밍·자원·신뢰성/오류처리·안전메커니즘 진단·보안 등)로 분류.
- 모호/미검증 불가 요구사항은 `open_issues`로 보고.

### 3. 기법 적용 (references/techniques.md 상세)
| 기법 | 적용 | 비고 |
|---|---|---|
| 동치 클래스 (EP) | **필수** | 유효/무효 클래스 모두. 클래스당 대표값 1개, 중복 금지 |
| 경계값 분석 (BVA) | **필수** | 수치/시간/카운터/상태 임계에 대해 min-1, min, min+1, max-1, max, max+1. 불연속·부동소수점은 분해능 단위 |
| 페어와이즈 | 입력 파라미터 ≥3개이고 상호작용이 있을 때 | **반드시 PICT** 사용. 직접 조합을 손으로 만들지 않는다 |
| WoW 검증 | 엣지 케이스 | `techniques`에 `WoW 검증`으로 명시 (아래 참조) |
| 요구사항 분석/오류 추정/결함 주입 | 선택 | ISO 26262-6 도출 방법. 안전 메커니즘은 결함 주입 TC 고려 |

**EP/BVA 분석 결과는 `analysis`에 기록**(TB ID, 파라미터, 클래스/경계, 값)하고, TC는 그 값을 인용한다. 분석표에 있는 클래스/경계가 TC 어디에도 없으면 누락이다.

### 4. PICT (페어와이즈)
```
python .claude/skills/system-test-skill/scripts/run_pict.py model.txt [--order 2] [-o out.tsv]
```
- 모델: `Param: v1, v2` / 제약 `IF [A]="x" THEN [B]<>"y";` / 무효값은 `~` 접두(PICT가 무효값을 케이스당 1개로 격리).
- 파라미터 값은 EP/BVA에서 나온 대표값만 사용. 안전 중요(ASIL C/D) 상호작용은 `--order 3` 고려.
- 실행파일이 없으면 `run_pict.py`가 안내/다운로드(`gh release download -R microsoft/pict`, 출처: https://github.com/microsoft/pict). 다운로드 전 사용자에게 알린다.
- PICT 출력 행 1개 = TC 1개 후보. 물리적으로 불가능한 조합은 제약으로 제거(불가능 TC 금지). 모델과 출력은 `pict` 섹션에 보관해 재현성 확보. `techniques`에 `페어와이즈(PICT)` 표기.

### 5. 엣지 케이스 — WoW 검증
엣지(상태 전이 경계, 시작/종료/재시작, 전원 순단, 통신 지연·유실·중복, 동시 이벤트, 극한 환경, 오버플로, 클럭 롤오버, 모드 전환 중 입력 등)를 체계적으로 찾아 TC화하고 `techniques`에 **`WoW 검증`**을 명시한다. TB에 연결 가능하면 TB ID를, 도출 근거가 내 추정이면 `suggested: true`.

### 6. 비기능 TC
성능(응답시간, 주기, 지터), 자원(CPU/메모리/스택, ISO 26262-6 자원 사용 평가), 신뢰성/오류 처리·안전 상태 전이(FTTI 내 반응), 타이밍·부하·장시간(soak), 호환성, 보안 등. 측정 방법·합격 기준 수치 필수. 시트는 `비기능 TC`.

### 7. 산출 및 검증
1. 중간 JSON 작성 (스키마: `references/schema.md`).
2. 실행:
```
python .claude/skills/system-test-skill/scripts/build_xlsx.py tc.json -o SystemTestSpec.xlsx
```
(의존성: `pip install openpyxl`)
3. 스크립트가 검증 실패(미커버 TB, 고아 TC, 필수 기법 누락, 모호어, 빈 필드)를 보고하면 **TC를 수정/추가하고 재실행**. 통과 전에는 100% 달성을 보고하지 않는다.
4. 산출 시트: `기능 TC`, `비기능 TC`, `추적성 매트릭스`, `EP-BVA 분석`, `PICT`, `요약`(커버리지 수치·제안 TC 수·미해결 질문).

### 8. 최종 보고 (간결하게)
커버리지/추적성 검증 결과 수치, 제안 TC 개수, `open_issues`, 가정 사항. 파일 경로 제시.

## 규격 정합 (요약)
- **A-SPICE**: SYS.5(시스템 적격성 테스트)/SWE.6(SW 적격성 테스트) — 테스트 명세에 TC 포함, 테스트 대상 요구사항과 **양방향 추적성**, TC 선정 기준, 일관성 보장. 상세는 references/techniques.md.
- **ISO 26262-6**: 요구사항 기반 테스트, TC 도출 방법(요구사항 분석·동치 클래스·경계값·오류 추정), 인터페이스/결함 주입/자원 사용 평가, ASIL별 권고 수준. 표 번호는 적용 판(2011/2018)을 확인 후 인용.
